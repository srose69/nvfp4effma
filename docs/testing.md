# Testing

`make test` runs the C tests below on GPU `$(GPU)` (default 0); the exhaustive checks take a few seconds
on a GTX 1080. `make test-sm60` builds the library for sm_60 only and runs the GEMM / GEMV tests against
it: on an sm_61+ GPU that SASS runs (binary compatible), so it exercises the code of GPUs without DP4A —
the FFMA NVFP4 × NVFP4 kernels — and the default kernel tables. `make test-sm75` builds it from compute_75
PTX only: on an sm_80+ GPU the driver JIT-compiles it and the tensor-core kernels run their Turing variant.

| Test | What it checks |
|---|---|
| `tests/test_gemm.cu` | `nvfp4a_gemm`, tiled kernels, bit-exact against a host emulation of the documented order: NVFP4 A × B in {NVFP4, INT8, BF16, FP16, FP32}, m / n tails, padded `ld` and `ld_scale`, global scales, every output dtype, C of another dtype, accumulation into D, α / β / bias / amax, zero block scales, larger problems; every operand format (all 128 combinations of swizzled / UE5M3 scales of A and B, amax globals on A, B or both with `scale_max` 448 / 256, per-row globals of A and B) for NVFP4 B, the 16 without B flags for the other B dtypes — the DP4A wide and narrow tiles, and the FFMA kernels with `make test-sm60`. |
| `tests/test_gemv.cu` | The GEMV path, bit-exact against an emulation of its lane order: x in {NVFP4, INT8, BF16, FP16, FP32} × n = 1 … 8, every output dtype, accumulation, bias, k not a multiple of the 512-value pass; n = 12 … 49 (groups of 8) on both sides of the GEMV limit; every operand format as in `test_gemm.cu`, n = 1 … 20 (groups with swizzled x scales and per-row x globals). |
| tensor cores (in `test_gemm` / `test_gemv`) | On sm_75 … sm_89, every case of the two tests also through `nvfp4a_tc_image` + `nvfp4a_gemm_tc` (B NVFP4, INT8, BF16) and, for n ≤ 8, `nvfp4a_gemv_tc` on the same image of A, against a float64 reference within the bound of an FP32 accumulation over k plus the output's rounding (the tensor cores' order is not the emulated one); amax within the same bound. |
| `tests/test_images.cu` | Weight images: A16 ↔ A8 conversion equals building the other kind from the tensor, and image → tensor gives it back byte for byte with padded pitches untouched, for row counts and k that leave partial slices, records and groups. |
| `tests/test_nvfp4effma.cu` | The DP4A scale step (`fma(1.5·2²³ + p, sa, −1.5·2²³·sa) = p·sa` for every block sum of W4A4 and W4A8, \|p\| ≤ 24384, and every finite scale); the PRMT int8 decode on all 2¹⁶ inputs and the FP32 decode of every nibble at every position; exactness of the dense-B operands (`a·sa` times every BF16 / FP16 value, 2²⁸ cases each); FP32 → BF16, E2M1 and E4M3 rounding on all 2³² FP32 bit patterns against independent midpoint searches; UE5M3 encoding on all 2³²; the branchless E2M1 conversion and the reciprocal division of 4over6 (`div_by`, both denominators) on all 2³² against `f32_to_e2m1` / IEEE division; `nvfp4a_quantize` (to NVFP4 and to INT8) / `nvfp4a_quantize_ex` / `nvfp4a_dequantize` bit-exact against a host emulation of Transformer Engine's arithmetic — 1 × 16 and 16 × 16, 4over6 MAE / MSE, amax given or computed (per tensor and per row), swizzled and UE5M3 scales, rowwise and columnwise, BF16 / FP16 / FP32, partial tiles — with zero, underflowing and saturating blocks; `nvfp4a_transpose` of 16 × 16 tensors against the columnwise quantization; `nvfp4a_swizzle_scales` both ways. |
| `test_nvfp4effma -DNVFP4A_NEGATIVE_CONTROLS` | Five deliberately broken variants (the magic removed after rounding, decode without signs, RNE without NaN handling, E2M1 and E4M3 ties away from zero) must be rejected. |
| `binds/python/tests` | The PyTorch bindings (`pytest`): quantization bit-exact against an independent PyTorch reference of Transformer Engine's arithmetic for every recipe (1 × 16 / 16 × 16, 4over6, row-scaled, swizzled, UE5M3, columnwise = quantized transpose), dequantization in every scale layout, `linear` with every weight format and a W4A4 row-scaled swizzled activation, the backward GEMMs from columnwise halves, `NVFP4Tensor.from_te`, `linear` with dense, INT8 (`act="int8"`) and NVFP4 activations against a float64 reference (GEMV and tiled), batched inputs and accumulation, strided inputs, `NVFP4Linear` / `quantize_linear_`, `TCWeight` (tensor-core GEMV and GEMM, W4A16 / W4A8 / W4A4, against the same reference; skipped without a tensor-core path), and rejection of bad input. |
