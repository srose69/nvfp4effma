# Building, installing, tuning

## Requirements

- CUDA 12.0 or newer and GNU make.
- A host compiler your CUDA accepts. The Makefile uses `g++-12` when it is installed (CUDA 12.0–12.3
  reject GCC 13); otherwise nvcc's default. Override with `CCBIN=...`.
- PyTorch only for the bindings ([binds/python](../binds/python/README.md)).

## Make targets

```sh
make lib                    # out/libnvfp4effma.a for sm_50 52 53 60 61 62 70 72 75 80 86 87 89 90
make lib ARCHS=native       # only the architecture of GPU $(GPU), detected with nvidia-smi
make lib ARCHS="61 75 86"   # any subset
make test                   # bit-exact and exhaustive tests on GPU $(GPU) (default 0)
make test-sm60              # GEMM / GEMV tests against an sm_60-only build: on an sm_61+ GPU this runs
                            # the code of GPUs without DP4A and the default tables
make bench                  # GEMM / GEMV / quantization vs cuBLAS and memory bandwidth
bench/run_bench.sh          # controlled run (board settings, cool-downs) -> benches/<gpu>.md
make tune                   # tune the kernels for GPU $(GPU) -> src/nvfp4effma_tuned.h
make install PREFIX=...     # header, static library, pkg-config file
```

Variables: `ARCHS`, `GPU`, `CUDA_HOME` (default `/usr/local/cuda`), `CCBIN`, `JOBS`, `JOB_MB`,
`OBJDIR` (where the multi-architecture objects go), `PREFIX`, `DESTDIR`.

The library ships SASS only (no PTX), so it is never JIT-compiled onto GPUs it was not built for — in
particular not onto sm_100+, which has native FP4; building for those targets stops with `#error`. A
GPU missing from `ARCHS` gets a clear error at run time (`nvfp4a_last_error`).

## Parallel build

The build runs in parallel by default with `JOBS = min(cores, ½ · MemAvailable / JOB_MB)`
(`JOB_MB = 512`; one nvcc process peaks at about 110 MB). `make JOBS=n` overrides it; a plain `-j` on
the command line is overridden. When there are more job slots than objects, the objects also compile
their architectures in parallel (`nvcc --threads`).

Kernel instances are split into small objects of similar cost (GEMM: configuration × B dtype; GEMV:
configuration × x dtype), and each architecture's SASS contains kernel bodies only for the configurations
it can dispatch to (trapping stubs elsewhere): its table and the defaults, the DP4A kernel from sm_61, the
FFMA NVFP4 × NVFP4 kernel below. On a 20-thread CPU the library for all 14
architectures builds in about 36 s.

## Installing for C / C++

```sh
make install PREFIX=$HOME/.local ARCHS="61 75 86"
cc app.c $(pkg-config --cflags --libs nvfp4effma)     # PKG_CONFIG_PATH=$HOME/.local/lib/pkgconfig
```

The pkg-config file adds the CUDA include directory and `-lcudart -lstdc++`. Without installing,
include `include/nvfp4effma.h` and link `out/libnvfp4effma.a` plus the CUDA runtime. The library is
compiled with `-fPIC`, so it can be linked into shared objects (the Python extension does that).

## Tuning

`make tune` benchmarks every dense-B GEMM / GEMV candidate ([design.md](design.md#kernel-configurations)) on
GPU `$(GPU)` and writes the winners for its compute capability to `src/nvfp4effma_tuned.h`; entries
for other compute capabilities in that file are kept, so one table can be built on several machines.
A candidate replaces the default only if it is at least 2 % faster, so noise does not add kernels to
the library. Rebuild the library afterwards.

At run time the library uses the entry for the device's compute capability, or the defaults for GPUs
without one. A GPU that runs binary-compatible SASS of another minor version (say, a library built for
sm_60 on an sm_61 card) falls back to the defaults automatically, since that SASS only carries the
defaults' kernel bodies. The NVFP4 × NVFP4 path is chosen the same way, by the SASS the device runs: DP4A
from sm_61 SASS, FFMA below (this is how `make test-sm60` exercises the FFMA path on a GTX 1080). Tuned entries for GPUs other than the GTX 1080 are very welcome as pull
requests.

## Project layout

```
include/nvfp4effma.h          public C API
src/nvfp4effma.cuh            core: exact E2M1 / E4M3 decode, PRMT int8 decode, E2M1 / E4M3 / BF16
                              rounding, typed loads / stores, GEMM / GEMV epilogue, kernel tables
src/nvfp4effma.cu             nvfp4a_quantize / nvfp4a_dequantize, errors (nvfp4a_last_error), kernel
                              table and SASS version of the current device
src/nvfp4effma_tuned.h        tuning results (generated by `make tune`)
src/gemm_nvfp4effma.cuh       GEMM kernel templates (FFMA, DP4A) and the configuration candidates
src/gemm_nvfp4effma.cu        nvfp4a_gemm: validation, routing to GEMV, path and configuration choice
src/gemm_nvfp4effma_inst.cu   GEMM instances (one small object per configuration × B dtype)
src/gemv_nvfp4effma.cuh       GEMV kernel template and its configuration candidates
src/gemv_nvfp4effma.cu        GEMV configuration choice
src/gemv_nvfp4effma_inst.cu   GEMV instances (one small object per configuration × x dtype)
binds/python/                 PyTorch bindings: pip package `nvfp4effma`
tune/tune.cu                  tuner
tests/                        C tests (see testing.md)
bench/                        bench_gemm, bench_gemv, bench_quant; run_bench.sh + report.py (benches/)
benches/                      benchmark results: table.md (one row per GPU), <gpu>.md (full runs)
docs/                         this documentation
```
